# 图表选型与陷阱库

> 数据图的**呈现规范**。选型看「读者要拿它比什么」，不看「哪种好看」。
> 落地生成走 fworch-report 工作流 G（python 脚本 → 子文档）；本文件定义「画什么图、必须带什么、哪些错会改变结论」。

## 选型速查

| 读者要比什么 | 用 |
|---|---|
| 类别之间的大小 | 横条（类别名长）/ 竖柱（时间或有序） |
| 随时间的变化 | 折线；只有两点用箭头连接的圆点 |
| 构成比例 | 堆叠条；**别用饼图**除非只有 2–3 块 |
| 量表/正负分布 | 发散堆叠条 |
| 两个变量的关系 | 散点 + 直接标注 |
| 分布形态 | 直方图 / 箱线图 |
| 流向与转化 | 桑基 |
| 具体查数 | 表格 |
| 单一关键数字 | 大数字 + 一行说明，**别画图** |

## 每张图必须带六项

1. **标题**（结论式，研报型除外——见下）
2. **数据源行**（区分采数方和分析方）
3. **样本量 N**（**该图的 N**，不是全报告的 N）
4. **单位**（%、pp、美元、次/人）
5. **调研图另加问卷原题**
6. **编号**（学术 Figure / 研报 Exhibit，一份报告内不混用）

**图表标题写结论，不写主题。** ❌「按职能划分的招聘计划」 ✅「研发、销售、产品团队预计扩张，
客服和 G&A 预计收缩」。唯一例外是研报型——查数的读者要中性描述。

## 三个会改变读者结论的陷阱

这三个和「不好看」不是一个量级——它们会让读者得出错误的结论，而且不会有任何报错。

**一、负值被画成零高度。** 如果图表代码没处理负值，`-11%` 会渲染成 0 高度的柱子，
于是「下降 11%」和「没有变化」在图上完全一样。任何可能出现负值的数据，画完先确认：
零线在哪？负值在零线下方吗？标签有没有带符号？

**二、选错图型产生无意义的元素。** 用成对柱去画只有一组数据的对比，
第二根柱子会是 0 高度并老老实实标注「0%」——读者会以为那是个真实的零值。
**一组数据用横条，两组才用成对柱。**

**三、Y 轴不从零开始且不标注。** 把 3% 的差异画成三倍高。若确实需要截断坐标轴
（比如比较 97% 和 99%），必须在轴上明确标出断裂，并在图注里写明。**默认永远从零开始。**

## 常见坏做法

- Y 轴不从零开始又不标注——把 3% 的差异画成 3 倍
- 3D 饼图、阴影、渐变填充——装饰墨水挤占数据墨水
- 双 Y 轴——两条轴的缩放可以拼出任何想要的「相关性」
- 图例在图外很远处——读者在两处之间来回跳
- 用彩虹色做有序数据——彩虹在感知上不是单调递增的
- 只用颜色区分——约 8% 男性有色觉障碍，形状/位置/直接标注要能独立工作

## 排版层交付自检（渲染后逐图看）

机械查不出的（必须看图）：

- [ ] **列缝粘连**：相邻列内容贴死，读起来像「84%尚未围绕…」这种连成一句的假句子
- [ ] **负值画成零高度**：零线在哪？负值在零线下方吗？
- [ ] **图表标注被版心切掉**：凡是给文字预留固定空间的写法都会这样，而 SVG 不报溢出
- [ ] **居中标注在最边上那个点被切**（时间轴、折线末端标注最容易）
- [ ] **视觉锚数字被拦腰折断**：「626,15 / 5磅」
- [ ] **双列组件里某一列塌成一个字宽、整段竖排**
- [ ] **坐标轴刻度被格式化成一串相同的数**：画 0.90–1.70 这种窄区间时，刻度全印成「1,1,1,2,2」，纵轴报废
- [ ] 图表容器远大于内容，页面下半空着

> **抽检对图形缺陷无效。** 缺陷不是均匀分布的，集中在最复杂的那几页——长表格、宽图表、附录。
> 逐图看过，不能抽看。
