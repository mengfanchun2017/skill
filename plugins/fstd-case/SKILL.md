# fstd-case — 案例库内容规范（L2）

横向规范层，定义「一条好的案例长什么样」。**不绑定执行**（编排/检索/建库走 `orchcase`），**不重复平台格式**（飞书格式硬约束走 `fstd-core`）。

## 职责边界

| 本 skill 负责 | 不负责（委派） |
|--------------|--------------|
| Base 字段 schema | 飞书格式 → `fstd-core` |
| 案例起名规则 | 编排/检索/建 wiki 执行 → `orchcase` |
| 摘要格式 | 材料解析 → `orchcase` + MinerU |
| 正文模版 + 写作要求 | 搜索扩展 → `fsearch` |

## Base schema（15 字段，2026-09-26 重构后）

| 列 | 字段 | 类型 | 说明 |
|----|------|------|------|
| 1 (主键) | 案例名称 | text | 起名规则见下，主字段固定首列 |
| 2 | 编号 | auto_number | 4 位 `0001` 自动递增（飞书限制主字段不能 auto_number）。**字段名 `编号`，非 `案例编号`** |
| 3 | 公司 | text | 原名「公司/品牌」，2026-09-26 改名 |
| 4 | 行业 | select(多) | 零售/航空/快消/金融/科技/汽车/医药/制造/教育/其他 |
| 5 | 地区 | select(多) | 北美/欧洲/亚太/中国大陆/其他 |
| 6 | 案例年份 | number | |
| 7 | 专业领域 | select(单) | 原「方向」+「主题领域」合并。**单选**：数字转型/客户细分/个性化推荐/预测性维护/增长策略/运营效率/风险管理/数字化营销/供应链/组织管理/其他 |
| 8 | 业务职能 | select(多) | 市场/销售/运营/供应链/财务/人力/IT/数据/客服。⚠️ **`IT/数据` 是一个选项**（含斜杠） |
| 9 | 案例类型 | select(多) | 数字化转型/业务增长/失败复盘/竞争分析/新品上市/运营优化/其他 |
| 10 | 分析方法/模型 | select(多) | RFM/漏斗分析/聚类/预测建模/回归分析/数字孪生/A/B测试/因果推断/其他。⚠️ `A/B测试` 含斜杠 |
| 11 | 摘要 | text | **清单体**，见下 |
| 12 | 数据源链接 | text(url) | |
| 13 | 案例主文档 | text(url) | 第2层 docx 的 URL |
| 14 | 案例状态 | select(单) | 已上线/草稿/待审核 |
| 15 | 更新时间 | updated_at | 系统字段 |

**已删除字段**（2026-09-26）：公司规模/子文档列表/教学目的/内容形态/热门/创建时间/难度/数据能力要求。

**业务职能坑**：`IT/数据` 是一个 select 选项。写 `["IT/数据"]`，写 `["IT","数据"]` 报 `not_found`。

## 案例起名规则（统一，可复现）

```
案例标题 = {公司} - {分析工具/动作} - {分析目标/结论}
例：
  Starbucks-RFM与客户分层-忠诚度 （RFM 客户分层 → 忠诚度提升）
  GE Aviation-数字孪生-预测性维护（数字孪生 → 预测性维护）
```

- 「分析工具/动作」取自「分析方法/模型」字段（RFM/数字孪生/聚类...）
- 「分析目标/结论」一句话浓缩案例核心业务价值
- 第3层子文档标题 = 主文档标题 + `-子内容名`（如 `-漏斗图`、`-数据集`）
- 勿用"XX 商业分析案例"这类看不出内容的旧名
- **更新版**：`{YYYYMMDD} {公司}-{动作}-{目标}`（日期 = 最新事件日期），挂原案例 wiki 节点下

## 摘要格式（清单体，不写长句）

```
- 公司/业务：{公司名}（{一句话业务描述}）
- 分析动作：{分析方法/模型}
- 目标：{案例要解决的业务问题}
```

例：
```
- 公司/业务：Starbucks（全球咖啡连锁）
- 分析动作：RFM 客户分层 + 聚类细分
- 目标：个性化推荐 + 忠诚度体系
```

## 案例正文模版（所有案例统一结构，2026-09-26 定）

> 案例正文 = 一份飞书在线文档（docx）。**文档标题 = 案例名，正文主节直接用一级标题 `#`**，不重复写案例名作标题。两级结构：`#` 大节 + `##` 小节，扩展内容里的新闻条目也是 `##`，不出现 H4。

```
（文档标题 = 案例名，正文不再重复案例名作标题）

# 案例概述          ← 1-2 段：公司一句话、所在行业、核心业务挑战、用到的分析方法
> 原链接：{原始资料 URL}      ← 标题下第一行用引用标记原链接

# 公司 / 行业背景    ← 可省略；讲清业务场景才需要
## 公司简介          ← 业务模式、主要产品/客户
## 行业环境          ← 竞争/变化，为什么这问题重要

# 业务挑战           ← 核心：公司面临什么问题（决策点/两难），教学案例要有"待解问题"
> 原文：{英文原文}    ← 重点中文段落下用引用标记英文原文

# 分析方案           ← 用数据分析/模型怎么解决
## 方法              ← 分析方法/模型（RFM/数字孪生/聚类...）
## 实施              ← 具体做法
（图表/代码 → 放第3层子文档，正文用链接引用）

# 成果与影响         ← 可量化结果（数字优先）
（列表用飞书有序列表 1. 2.）
（有数据表格 → 飞书原生表格 XML）

# 扩展内容           ← 深度搜索相关新闻/分析，总结并附链接（必写）
## {YYYYMMDD} {新闻标题}   ← 每条新闻/分析独立成一个 H2，标题 = 日期(YYYYMMDD) + 空格 + 主题
                            正文下放来源链接；不加"最新动态/深度分析"这类引导行
                            （多条按日期降序排列）

（可选附录，放文末或子文档）
# 数据集与附录       ← 数据表转飞书表格；图表/代码子文档
# 原始资料           ← 引用来源列表
```

**标题层级**：正文从 `#`（案例概述）起步，小节 `##`，扩展内容每条新闻也是 `##`（标题 `YYYYMMDD 主题`）。旧文档若主节是 `##`/`###` 需整体上移一级。

**扩展内容规则（必写）**：
- 用 tavily/exa 深度搜索与案例主题相关的最新（近1-2年）新闻与分析文章
- **不写"最新动态与深度分析"这类引导行**，直接进入各条目
- 每条 = 一个 `## YYYYMMDD 标题`（标题以日期 + 空格开头，如 `## 20260310 忠诚度体系三层改版上线`）
- 标题下一段 1-2 句总结（含关键数据/结论/时间），末尾放 `来源：[标题（日期）](URL)`；来源标注 [tavily]/[exa]
- 多条按日期降序；搜不到直接相关则写行业最新动态或数据

**写作要求**：
- 客观中立叙述（教学案例规范）：不写"作者认为/值得学习"这类评述，只陈述事实
- 明确事件时间/年份；不用"目前/最近"
- 数据/表格要有来源；关键数字给具体值（3,000 万+活跃会员 而非"很多"）
- 列表用飞书有序列表（markdown `1.` 渲染成飞书原生有序列表），不手写 a./b./c.
- 数据表转飞书原生表格，不堆图片截图
- 图表从原链接复制嵌入飞书（和案例相关的那张），其余放第3层子文档
